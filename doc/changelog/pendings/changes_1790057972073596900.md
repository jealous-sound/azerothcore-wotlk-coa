### Fixed

- Adventure Mode accepts any tier. Entering a level required the level below to be completed
  first, which turned a difficulty picker (1-100) into a ladder: a fresh character could only take
  tier 1 and the reported tier 30 or 32 was refused with "Complete the previous level of Adventure
  Mode first". The requirement is gone. Entering at a higher tier is not a shortcut, because
  rewards are paid per `(challenge, level)` completion row, so a high tier pays exactly what its own
  completion pays and nothing below it.

- The loot-interaction requirement no longer locks a multi-level challenge. Adventure Mode's
  definition carries it (the client's own data lists it too), and it is evaluated against a
  lifetime "has looted" flag, so every level of a mode whose whole loop is dungeon loot was closed
  to any character that had ever opened a corpse. The gate now applies to single-level challenges
  only, which is what it is for: a clean start for a one-shot run such as Slow and Steady. It is
  still enforced there, unchanged.

- Trials pay their rewards, then record the completion. Rewards were granted after the
  `coa_challenge_completion` row was written, in the same path that ends the trial - so a failed
  grant, or a realm drop in between, consumed the trial and paid nothing, with no way to retry. The
  grant now happens while the challenge is still recorded as active and the completion row follows,
  which is the order that cannot lose a reward. The trial ending, and its debuff coming off with it,
  is unchanged.

- Centenarian Bullion (413799) sells to a vendor for 50 gold again. Its sell price was a tenth of
  the value its own denomination implies: Centenarian Coin (413800), the smaller unit, sold for
  2,500 gold against a 10,000 gold buy price, while the Bullion sold for 500 gold against a
  10,000 gold buy price. The Bullion now keeps that same 2:1 relation to its buy price.

- The Witch Hunter's caltrops render at field-prop size. The prop (creature 506010) draws display
  401941, whose only model is the Outland passive doodad `Caltrop01.mdx` - the same display the
  hidden cauldron uses - so spawning it at scale 1.0 made a doodad-sized mesh stand in for a trip
  marker. Both client-side scale factors for that display are 1.0, so the server value is the only
  lever; the trigger radius the field code uses is untouched, so only the visual size changes.

- A Rune of Ascension Pouch pays its runes when it is right-clicked. The pouch carries
  `ITEM_FLAG_HAS_LOOT`, so the client asks to open it (`CMSG_OPEN_ITEM`) and never to use it: the
  click was answered with an empty loot window and the pouch was consumed for nothing. The pouch
  script now answers the open as well, paying the amount its own name states into the Currency tab,
  spending the pouch only once those runes fit, and refusing the loot window. The binding was
  missing as well - `item_template.ScriptName` named no script for any pouch row - so the handler
  was registered at startup and never called.

### Testing

- `apps/coa-gameplay-test/scenarios/challenges-refusal-wording.json` starts challenges through the
  client's own `CMSG_COA_START_CHALLENGE`. A fresh level-1 character asserts a start on tier 30 of
  Adventure Mode (answer code 0) and that nothing tells it to finish a previous level; a character
  that has looted a sack asserts a start on tier 32, and that no loot requirement is named; the
  same loot history on Slow and Steady asserts the refusal (code 8) with its sentence; a level-80
  character asserts the experience refusal with its own sentence and never the raw condition name.

- `apps/coa-gameplay-test/scenarios/ascension-reward-items.json` opens a pouch with the packet a
  client sends for it and asserts the pouch is spent once, that 52,000 Runes of Ascension land in
  the Currency tab, that a second pouch pays its own 12,500 on top, and that the largest rung is
  read from its own name (129,500 in total).

- `apps/coa-gameplay-test/scenarios/ascension-reward-data.json` asserts the Bullion's sell price
  from the loaded item template and the caltrop model's display scale, and, with a live Caltrops
  cast, that the scattered props are drawn at that same scale while the shared hidden cauldron
  stays at full size.

- The harness gained what those assertions need: `token_count` (currency slots, which `item_count`
  cannot see), `item_sell_price`, `creature_model_scale`, `owned_creature_scale`, `unit_scale`,
  `system_message_contains`, `challenge_start_responses`, `challenge_start_code`, and the
  `start_challenge` action that submits the client's challenge request through the module that
  answers it.
