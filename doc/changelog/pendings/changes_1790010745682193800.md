### Fixed

- Ranks of an ability sold by the Books of Ascension are gated on the rank directly under them
  again. Every row of a ladder carried the ladder's first rank as its requirement, so as soon as
  the second rank was bought the client greyed every rank above it for an ability the character
  no longer held: the requirement line read "requires <ability> (Rank 1)" on the still-unbought
  ranks and the Train button was dead until the book was reopened. A row now requires the rank
  directly beneath it, which is what the original trainer window published and what the client
  checks, and a purchase refuses a rank whose prerequisite is missing instead of learning it.

- A rank bought from a book is announced once in chat instead of twice. The core answers a rank
  up with `SMSG_SUPERCEDED_SPELL`, which the client announces itself, and the window was sending
  its own `SMSG_LEARNED_SPELL` on top of that cue. The window no longer announces anything: an
  ability the character did not have is announced by the core, and a rank up by its supersede cue.

- A rank the character already holds stays in the window as a used row instead of leaving it, the
  way `Trainer::GetSpellState` marks a known spell at a stock trainer. A republished window
  therefore holds the same rows in the same order as the one on screen, so the row the player was
  working in does not renumber under them.

- A book no longer sells a rank the character already holds above it. Such a row is not an upgrade:
  `Player::addSpell` only moves the spell into the active spec and announces nothing for it, while
  the rank it pulls into that spec - the one the character already had - is announced instead. A
  purchase could therefore show a chat line for a rank the player had not bought and none for the
  rank they had. The window treats a row as known when the character holds a rank above it, read
  from the rows' own rank links, because the core's spell chain does not cover every custom ladder.
  The rank above a held one is still sold normally.

### Testing

- The gameplay harness reads a row's requirement and counts supersede cues per spell, so a
  scenario asserts which rank a row needs and that no purchase is announced twice
  (`trainer_window_ability`, `spellbook_superseded_packets`, `spellbook_superseded_for`,
  `spellbook_silent_buys`, `spellbook_multi_announced_buys`).

- It also judges a purchase by the cues it produced: `spellbook_cues_in_last_buy` counts the
  announcements made between two purchases and `spellbook_last_buy_cued` says whether one of them
  named a given ability, so a scenario asserts that a purchase announced the rank that was bought,
  exactly once, and that a refused purchase announced nothing.

- New scenarios: `apps/coa-gameplay-test/scenarios/books-rank-refresh.json` (a ladder bought in a
  row, the list unchanged, one cue per rank), `books-announcements-rank-above.json` (a row under a
  held rank is not offered, is refused, and announces nothing; the rank above it is granted with a
  single cue naming it) and `books-announcements-first-ranks.json` (first ranks bought from the
  window are each announced once, by the rank that was bought).
