### Added

- The Prestigious and Callboard Caches are handed out and open again. Both families are the
  progression caches: a named cache pays one item from its own content, a generic cache resolves
  the content the opener has reached, and the two later-era generic Callboard rows resolve from the
  opener's average equipped item level, which is what that row's own text promises. Every row that
  used to open nothing but its dummy trigger spell now pays out. Seventeen named Prestigious Caches,
  thirteen Callboard Caches and three generic rows are bound to their handler; a named Prestigious
  Cache still arrives through its on-use spell, while the Callboard rows carry
  `ITEM_FLAG_HAS_LOOT` and arrive through the client's own `CMSG_OPEN_ITEM` request, so both paths
  open the same cache and neither leaves a loot window behind.

- Every pool pays only the content it names, and it is complete for that content. Each pool is
  built from the item's own `@...@` source tag - `@Heroic Dungeon@`, `@Mythic Dungeon@`,
  `@Molten Core@` and so on - so a Heroic Dungeon Cache pays heroic dungeon gear, a Mythic Dungeon
  Cache mythic dungeon gear, and a raid cache that raid's own gear. A Heroic, Mythic or Ascended
  copy of an item, an item the item text itself calls deprecated, an out-of-era row, a quest item
  and a mount are all outside every pool. A raid whose gear carries no per-raid tag, which is every
  Burning Crusade raid in this world, contributes its own loot table instead: the epic drops of the
  creatures on that raid's map with reference loot followed through, minus the twenty-six Outland
  world-drop epics that nearly every Outland map pays and that belong to no raid. The pools are
  also filled out with the raid's own loot rows that never received a difficulty copy, so the nine
  class bracers Blackwing Lair drops, the Zul'Gurub weapons and Shadow Panther hide, the Eye of
  Divinity, the Ruins of Ahn'Qiraj drops, the Gloves of the Fallen Prophet and the Arcanite Ripper
  are all in the cache of the raid that drops them.

- A tier token belongs to the content its reward comes from instead of to a global tier ladder.
  `ascension_cache_content_token` keys each of the fifty-one tokens to the caches that may pay it,
  and each row records the evidence that placed it: the map the token itself drops on, the items it
  buys through the vendor cost table in `ItemExtendedCost.dbc`, or the content of its own tier whose
  loot covers the slot its text names. A cache may only pay a token of its own content, so a Molten
  Core Cache pays the eight Molten tokens, an Onyxia's Lair Cache the Chromatic Headpiece, a
  Blackwing Lair Cache the seven Chromatic tokens, a Ruins of Ahn'Qiraj Cache the three Ceremonial
  Qiraji accessory tokens, a Temple of Ahn'Qiraj Cache its eight set tokens and a Sunwell Plateau
  Cache the four Sunwell tokens, while the Heroic Dungeon, Mythic Dungeon, Zul'Gurub and Zul'Aman
  Caches pay none at all because no token of those contents exists. Placement is intersected with
  the token's own tier, so a stale content tag on a Tier 5 or Tier 6 token's reward cannot drag it
  into a vanilla raid: the Helm of the Vanquished Defender stays with the Serpentshrine Cache and
  the Helm of the Forgotten Conqueror with the Battle for Mount Hyjal Cache, which is where each one
  drops. The realm's released stage still holds back a tier that is not live yet.

- A cache payout can no longer lose a reward, and a full inventory costs the player nothing. Gear
  and tokens take the same path: each reward is stored in the bags and then counted, anything the
  bags cannot take is posted by The Postmaster through the mailbox the game already uses for
  recovered loot, and the cache is destroyed only once every reward is either carried or posted, so
  it is still spent exactly once. A token is no longer skipped because the bags were full, which is
  how a token that had already been won used to disappear without a trace. When something is
  posted, the player is told in chat and on the centre of the screen: "Your bags were full, so your
  reward was sent to your mailbox.", or "...all N of your rewards..." for more than one item. Both
  go to the session that opened the cache and to nobody else, the mail is created for the opener's
  own GUID, and the item push is sent without a party broadcast.

- The reward pools and the token list are reloadable. `.reload config` re-reads both without a
  restart, which also re-applies the released stage, the Classic and Burning Crusade released
  counts, the generic Callboard item level allowance and the token chances. The new settings are
  `Ascension.PrestigiousCache.ReleaseStage`, `.TokenChancePercent`, `.SecondTokenChancePercent`,
  `.ClassicStages`, `.TbcStages`, `Ascension.CallboardCache.ReleaseStage`, `.PreviousStageOnly` and
  `.ItemLevelAllowance`, and each takes its documented default when absent.

### Fixed

- The Adventurer cache no longer pays into a destroyed item. It used to destroy the cache first and
  then store each reward with its own independent space check, silently skipping any reward that
  did not fit and broadcasting the push to the whole party. It now hands its rewards to the same
  all-or-nothing payout as the other families, so nothing is lost, the cache is spent once, and the
  reward is private to the opener. A cache whose reward row names an item that does not exist is
  still refused before anything moves, with the cache kept, because that is a data error rather
  than a full bag.

- The Rune of Ascension Pouch pays before it is consumed. It used to be destroyed first and only
  pay if the runes could be stored afterwards, so a store that failed cost the player the pouch.
  The runes are stored and counted first, and the pouch is consumed only once they are actually in
  the Currency tab; a pouch that cannot pay anything is kept instead of spent.

### Testing

- `apps/coa-gameplay-test/scenarios/ascension-reward-items.json` grows to 243 steps and 146
  assertions and passes on the realm binary. It opens each family both ways the client does, reads
  the pool each cache owns, and asserts that exactly one carried item is in that cache's own pool,
  that a neighbouring content's pool is untouched, that the cache is spent exactly once and that no
  loot window is left behind. It proves the token rules end to end: a Heroic Dungeon or Zul'Gurub
  Prestigious Cache leaves the opener with its reward and nothing else, because those contents pay
  no token. It fills every bag slot with a new `fill_bags` fixture and then opens a Heroic Dungeon
  Cache and a Molten Core Cache, proving each cache is still spent, that nothing entered the bags,
  that the reward and any token were posted (`mail_count`, `mail_item_count`, `mail_has_item`,
  `mail_pool_item_count`), that the notice reached chat and the centre of the screen
  (`system_message_contains`, `notification_contains`), and that a second character standing by
  gained no item, no mail and no notice. It also reads every pool directly and asserts that no pool
  holds a difficulty copy or a retired item (`pool_variant_count`, `pool_retired_item_count`), that
  each raid cache still holds the raid's own loot rows and at least as many rows as the raid has
  (`pool_item_present`, `pool_row_count`), and that every reward a cache paid is a normal row
  (`carried_variant_item_count`). The harness gained the `fill_bags` action and the cache, pool and
  mail metrics listed above, documented in `apps/coa-gameplay-test/README.md`.

### How to upgrade

Apply the world updates that ship with this change:
`data/sql/updates/pending_db_world/rev_20260921_60_ascension_prestigious_cache_rewards.sql` and
`rev_20260922_03_ascension_callboard_cache_rewards.sql` build the reward tables,
`rev_20260922_05_ascension_cache_content_tokens.sql` builds the content-keyed token table and drops
the superseded `ascension_cache_global_token`, and
`rev_20260921_61_ascension_prestigious_cache_scripts.sql` and
`rev_20260922_04_ascension_callboard_cache_scripts.sql` bind the item templates to their handler.
The Rune of Ascension Pouch binding already exists in
`rev_20260921_22_ascension_rune_pouch_scripts.sql` and is not repeated. The new settings take the
defaults documented above when they are absent.
